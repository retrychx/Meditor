# MEditor 产品演化方向分析

> 日期：2026-06-14 · 性质：独立视角，非路线图复述

---

## 一、先说现状判断

代码结构比现有 PRD 描述的成熟得多：

- `TemplateStore.swift` — 模板系统已有
- `PreviewThemeStore.swift` — 多主题已有
- `DocumentCommentStore.swift` — 注释/批注系统已存在（路线图几乎没提）
- `WebViewPool.swift` — 已做 WebView 性能优化
- `JSBridge.swift` — JS ↔ Swift 桥接已搭好

**结论：产品基础比看起来扎实，真正的问题是缺少一个让人记住它的理由。**

现有路线图的问题不是方向错了，而是每一项都是"竞品有我也要有"，没有一项是"只有我才能做好的"。

---

## 二、值得做的方向（按价值排序）

### 🏆 第一优先：AI 写作助手

**这是 2026 年最不该缺席的功能，也是最大的差异化机会。**

现有路线图完全没有提 AI，这是最大的盲区。

不是指做一个笨重的侧边栏 AI 面板，而是做**自然嵌入写作流的轻量 AI**：

| 功能 | 触发方式 | 价值 |
|------|----------|------|
| 续写/补全 | `Tab` 键接受 | 减少写作停顿 |
| 选中文本改写 | 右键 → AI 润色/简化/翻译 | 文档质量 |
| 从大纲生成草稿 | 写完标题列表后一键展开 | 提效最明显 |
| AI 文档诊断 | 不只检查格式，还能检查内容逻辑 | 超越规则引擎 |
| 智能模板填充 | 根据文件名/上下文自动填 frontmatter | 减少重复劳动 |

**为什么 MEditor 做 AI 比其他工具更合适：**
- 纯原生 macOS，无 Electron，AI 响应流式渲染不卡顿
- 已有 `JSBridge` + `WKWebView`，接入流式 API 技术难度不高
- 已有 `TemplateStore`，AI 生成内容可直接存为模板
- 定位本地工作流，AI 可以读取工作区上下文（其他工具做不到）

**实现路径（渐进）：**
```
第一步：右键菜单 → 调用系统级 AI API（macOS 26 Writing Tools）
第二步：接入自定义 API Endpoint（内网 LLM）
第三步：工作区上下文感知（跨文件参考）
```

---

### 🥈 第二优先：macOS 系统深度集成

**这是原生应用的护城河，Electron 竞品永远做不好的地方。**

| 集成点 | 价值 | 难度 |
|--------|------|------|
| **Spotlight 索引** | 文档内容全局可搜索，不用打开 App | 低 |
| **Quick Look 插件** | Finder 空格预览 Markdown 渲染效果 | 中 |
| **Shortcuts App 支持** | 自动化：定时导出、批量转换、分享 | 低-中 |
| **Share Sheet 集成** | 系统级分享菜单（配合 GitLab Snippet）| 低 |
| **Continuity Camera** | iPhone 直接拍照/扫描插入文档 | 低（系统提供） |
| **Focus Filter** | 专注模式时自动切换工作区 | 低 |

**Spotlight 索引**尤其值得做：用户在 Finder 搜索关键词，直接找到 Markdown 文件并高亮，这是 Obsidian 和 Typora 都没做好的。

---

### 🥉 第三优先：企业文档流转集成

**面向团队，不只是个人工具。**

已有局域网分享 + 今天设计的 GitLab Snippet，这条线继续延伸：

```
GitLab Snippet（已设计）
    ↓
内部文档平台发布（内部文档平台 / Confluence 适配器）
    ↓
MR 关联：文档变更 → 自动触发 MR 评论
    ↓
文档审阅流（基于已有的 DocumentCommentStore）
```

`DocumentCommentStore` 已存在，这说明批注功能有一定基础——**可以做轻量的异步文档评审流**：分享链接时，收到方可以在 GitLab Snippet 上评论，MEditor 本地感知并显示。

---

### 第四：全局搜索（路线图 V1 已有，确认是否实现）

这是最基础的短板，如果还没做，应该是最高优先级的基础设施。

---

## 三、不建议做的方向

| 方向 | 原因 |
|------|------|
| 实时多人协作 | 需要服务器基础设施，战线太长，且竞品（Notion/Confluence）已很成熟 |
| 双链笔记系统 | 和定位冲突，Obsidian 已经做得很好，跟随没意义 |
| 插件市场 | 过早平台化，用户基数不够时是负担 |
| CSV/JSON 预览增强 | 低频，非核心链路 |
| Vim 模式 | 边缘用户需求，维护成本不值 |

---

## 四、一句话总结

现有路线图做的是"填功能空缺"，真正有价值的方向是：

> **AI 写作 × 原生系统集成 × 企业文档流转**

这三个方向加在一起，能让 MEditor 成为"macOS 上最适合技术人写文档的工具"，而不只是"又一个 Markdown 编辑器"。

---

## 五、优先级矩阵

```
高价值
  │
  │   ① AI写作助手        ② Spotlight/Quick Look
  │   (差异化第一)         (原生护城河)
  │
  │   ③ GitLab分享完善    ④ 全局搜索
  │   (企业场景)           (基础必备)
  │
  └────────────────────────────────── 高实现成本
       低实现成本
```

**建议执行顺序：**
1. 全局搜索（如未完成）— 基础能力，不能缺
2. Spotlight 索引 + Quick Look — 1-2周，立竿见影，用户感知强
3. AI 写作助手 MVP — 先接 macOS Writing Tools，成本极低
4. GitLab Snippet 分享 — 已有方案，直接开发
5. AI 进阶（工作区上下文感知）
