## 1. 背景

MEditor 当前已经具备以下基础能力：

- 本地 Markdown / HTML 编辑与预览
- 工作区文件树、Tab、Quick Open
- Markdown TOC、滚动联动、预览内查找
- HTML / PDF / 图片导出
- 局域网分享、会话恢复、主题切换

现阶段产品最大的问题不是“功能太少”，而是缺少一条清晰的演进主线。继续零散堆功能，容易把产品做成既不像高质量文档工具，也不像 IDE 的中间态。

因此需要明确后续路线，统一产品目标、版本范围和研发优先级。

---

## 2. 产品定位

MEditor 的定位定义为：

**面向本地文档工作流的原生 macOS 文档工作台。**

它服务的不是重型代码开发，而是以下链路：

`打开文档 -> 编辑内容 -> 预览验证 -> 搜索定位 -> 导出 / 分享 / 发布`

产品重点应放在：

- 文档生产效率
- 文档质量保障
- 文档交付与分发

不应优先发散到：

- 通用 IDE 能力
- 重型代码智能
- 多人实时协作
- 花哨但低频的编辑器特性

---

## 3. 产品目标

### 3.1 总目标

在未来 6-12 个月内，将 MEditor 从“本地 Markdown/HTML 编辑器”演进为“可交付的文档工作台”。

### 3.2 分阶段目标

#### 阶段一：写得快

让用户能更快地创建、搜索、插入、改写内容。

#### 阶段二：交得稳

让用户在导出、分享、发布前，能发现常见问题并稳定交付。

#### 阶段三：接流程

让 MEditor 可以接入团队内部平台、Git 流程和文档发布动作。

---

## 4. 目标用户

### 4.1 核心用户

- 需要高频编写 Markdown / HTML 文档的产品、研发、运营人员
- 需要整理方案、设计说明、告警治理、复盘、周报等结构化文档的知识工作者
- 需要快速打开、预览、修订本地文档的 macOS 用户

### 4.2 典型用户特征

- 主要工作在本地文件系统和工作区目录中
- 文档通常需要预览确认格式后再交付
- 高频使用查找、目录跳转、导出、复制、模板化内容
- 对原生性能和稳定性敏感，不接受明显卡顿或预览错位

### 4.3 非目标用户

- 以代码编译、调试、语言服务为核心诉求的开发者
- 以多人协同编辑、评论流转为核心诉求的团队
- 需要在线知识库、双链、数据库视图等能力的重度笔记用户

---

## 5. 核心场景

### 场景 A：工作区内撰写方案文档

用户打开项目目录，快速定位某篇文档，补充内容，查看 TOC 和预览效果，并导出为 PDF / HTML。

### 场景 B：维护规范、README、治理文档

用户需要在多篇文档间搜索关键词，批量定位历史内容，统一修订格式或术语。

### 场景 C：快速接收外部素材并整理

用户将图片、HTML 片段、模板片段拖入文档中，快速形成标准化输出。

### 场景 D：交付前检查

用户在导出或分享前，检查标题结构、死链、缺失图片、重复标题等问题，避免低级错误流出。

### 场景 E：接企业内部发布流程

用户完成文档后，需要执行特定导出格式、复制富文本内容，或者一键发布到内部平台。

---

## 6. 产品原则

- 先解决高频工作流，再扩展低频能力
- 先做单机场景闭环，再考虑团队场景
- 先保证稳定性和一致性，再叠加复杂交互
- 以 Markdown / HTML 为主链路，不急于扩展更多文件类型
- 所有新功能都要考虑可测试、可观测和性能边界

---

## 7. 版本路线图

## 7.1 V1：内容生产效率

### 目标

降低用户创建、搜索、插入、改写文档内容的成本。

### 版本范围

- 全局搜索 `Cmd+Shift+F`
- 工作区内搜索结果跳转与命中高亮
- 图片粘贴 / 拖拽自动落盘并插入 Markdown 链接
- 文档模板与新建模板入口
- frontmatter 模板
- 片段库 / 常用块插入
- 最近文件 / 最近工作区
- 常用结构快捷插入：目录、链接、代码块、提示块

### 用户价值

- 减少重复输入
- 提升在大工作区中的定位效率
- 降低插图和整理文档的操作成本

### 验收标准

- 50k 文件级工作区可完成可用的全局搜索
- 结果跳转后能正确定位到编辑区或预览区上下文
- 粘贴图片后路径、落盘目录、插入语法一致且可配置
- 从模板新建文档的链路不超过 3 步

---

## 7.2 V2：质量保障与交付增强

### 目标

让用户在导出、复制、分享前更容易发现问题并稳定交付。

### 版本范围

- 文档诊断中心
- 发布前检查
- 导出预设
- Copy as Rich Text / HTML
- 文档统计信息
- 增强版 TOC：层级过滤、折叠、当前章节聚焦
- 多文档引用跳转与反向引用基础能力

### 诊断中心首批规则

- 死链
- 缺失图片
- 重复标题
- 标题层级跳跃
- 空标题
- 空链接
- 超大图片引用

### 用户价值

- 把常见交付错误提前暴露
- 降低从预览到分发的损耗
- 让文档工具具备“交付前保障”价值

### 验收标准

- 用户可在单一面板看到问题列表、严重级别、定位入口
- 导出前可一键执行检查
- 复制为富文本后的基本样式在常见办公工具中可读

---

## 7.3 V3：团队流程与平台接入

### 目标

将 MEditor 接入更完整的团队文档流转与工程流程。

### 版本范围

- Git 状态标记
- 当前文件 Diff 预览
- 命令面板
- 发布适配器
- 自定义脚本钩子
- 多窗口工作区
- 文档资产管理

### 用户价值

- 提升团队内规范文档维护效率
- 降低“导出后再二次加工”的成本
- 让产品成为工作流节点，而不是单独的编辑器

### 验收标准

- Git 状态信息展示不影响侧栏性能
- 发布适配器支持至少一个真实业务平台
- 自定义脚本失败时有清晰日志和错误反馈

## 8. 功能需求拆解

## 8.1 全局搜索

### 功能描述

提供工作区级内容搜索入口，支持多文件结果展示、上下跳转、命中上下文预览和替换。

### 核心要求

- 支持文件名 + 内容双维度搜索
- 支持大小写、正则、全词匹配作为后续扩展
- 搜索过程可中断、可复用索引
- 搜索结果分为文件级、匹配级
- 点击结果后定位到对应文件与位置

### 非功能要求

- 大工作区下首屏结果尽快返回
- 搜索过程不阻塞主线程
- 搜索结果更新有明显状态反馈

---

## 8.2 图片粘贴 / 拖拽落盘

### 功能描述

用户粘贴截图或拖入图片时，应用自动保存资源到指定目录，并插入引用语法。

### 核心要求

- 支持剪贴板图片和文件拖拽图片
- 支持配置默认资源目录，如 `assets/`、`images/`
- 支持文件重名处理
- 支持相对路径插入
- 失败时可回退并提示

---

## 8.3 模板与片段

### 功能描述

将高频文档结构沉淀为模板和片段，减少重复创建成本。

### 核心要求

- 支持从当前文档另存为模板
- 支持内置模板和用户模板
- 支持 frontmatter 占位符
- 片段可通过快捷入口插入当前光标位置

---

## 8.4 文档诊断中心

### 功能描述

扫描当前文档或整个工作区，输出可定位的文档问题列表。

### 核心要求

- 问题按严重级别分类
- 每条问题可直接跳转定位
- 支持按当前文档 / 整个工作区运行
- 支持导出或复制诊断结果

---

## 8.5 导出与发布预设

### 功能描述

将导出动作从单次手工操作提升为可复用的交付预设。

### 核心要求

- 支持导出 HTML / PDF / 图片的配置保存
- 支持复制富文本 / HTML
- 支持导出前执行诊断检查
- 支持后续接入发布平台

---

## 8.6 Git 状态与 Diff

### 功能描述

帮助用户在文档工作区内感知文件变更状态和当前内容差异。

### 核心要求

- 侧栏显示 `M / A / ? / D`
- 当前文件支持简化 diff 视图
- 不强耦合完整 Git 客户端流程

---

## 9. 非目标

以下能力不属于当前阶段重点：

- Vim 模式
- Minimap
- 大而全的语言服务
- 实时多人协作
- 笔记双链系统
- 云同步平台
- 插件市场

这些能力并非永远不做，而是在当前阶段不进入优先路线。

---

## 10. 成功指标

### 10.1 效率指标

- 用户可在 10 秒内完成工作区搜索并跳转到结果
- 用户创建模板文档的步骤数控制在 3 步以内
- 图片插入链路从拖入到完成引用小于 2 秒

### 10.2 质量指标

- 导出前检查可发现高频格式问题
- 导出后的内容与预览一致性稳定
- 主要交互链路无明显卡顿或错位

### 10.3 稳定性指标

- 大工作区搜索不阻塞 UI
- 文档诊断和导出失败时有明确报错
- 新功能接入后核心链路测试不回退

---

## 11. 技术依赖与约束

为支持本路线图，需要补齐以下基础设施：

- `WorkspaceIndexService`
  - 负责文件索引、全文搜索、结果模型
- `DocumentDiagnosticsService`
  - 负责规则化诊断和问题输出
- 统一预览桥接协议
  - 统一 TOC、查找、滚动联动、定位跳转
- 性能埋点体系
  - 覆盖搜索、预览刷新、导出、文件树刷新
- UI 集成测试
  - 覆盖搜索、TOC、导出、目录树、查找联动

如果没有这些支撑，后续功能会继续堆到 `AppState` 和若干 View 内部，维护成本会明显升高。

---

## 12. 风险与应对

### 风险一：功能持续堆叠，状态管理失控

应对：

- 优先拆出搜索、诊断、发布相关服务
- 减少把业务逻辑继续塞进 `AppState`

### 风险二：工作区搜索和诊断拖慢主线程

应对：

- 索引异步化
- 搜索结果分批返回
- 明确大工作区性能边界

### 风险三：交付能力过早平台化

应对：

- 先做通用导出预设
- 再按真实业务需求接具体平台

### 风险四：功能很多，但用户主线仍然不顺

应对：

- 所有版本都围绕核心路径验收：
  - 打开
  - 编辑
  - 搜索 / 跳转
  - 预览
  - 导出 / 分享

---

## 13. 里程碑建议

### Milestone 1

完成全局搜索、图片落盘、模板基础版。

### Milestone 2

完成片段库、frontmatter 模板、最近文件 / 工作区。

### Milestone 3

完成诊断中心基础版、导出预设、复制富文本。

### Milestone 4

完成 Git 状态、命令面板、性能埋点。

### Milestone 5

完成发布适配器、自定义脚本、多窗口工作区。

---

## 14. 结论

MEditor 下一阶段最合理的路线，不是继续向 IDE 演化，而是围绕文档工作流，逐步补齐：

- 内容生产效率
- 内容质量保障
- 内容交付与流程接入

只有这样，产品的能力边界、研发重点和长期价值才会保持一致。
